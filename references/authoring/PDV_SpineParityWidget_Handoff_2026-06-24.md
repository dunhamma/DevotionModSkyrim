# Spine-Parity Progress Widget — Tracker Handoff (2026-06-24)

## Purpose
A LIVING `show_widget` chart for the **ancestral-spine parity build** workstream: which races are
at parity, which remain, and the climb. Complements the existing living charts (build-arc history
+ projection-to-1.0 phased burnup) — this is the drill-down on the spine-parity workstream, which
is one of the pre-1.0 items. The "races-proven" / burnup lines can incorporate spine-parity as
`N/7 at parity`.

## Data source (THE key point — it's self-updating)
Read **`references/authoring/PDV_SpineStackScoreLedger.csv`** — it is regenerated by
`node tools/pdv_spine_stack_score.mjs` (which reads `PDV_SpineStackRegistry.csv`). Do NOT hand-key
values; re-run the tool and re-read the CSV. The integrity harness (`pdv_integrity_harness.mjs`)
also surfaces `spine_stack_score` summary if you want a one-liner.

### CSV data model (columns)
`race, pct, raw, target, boon_floor, piety_sink, minus_stack, renewable, diegetic, text_voice, richness, diegetic_dead, diegetic_wired`
- `pct` — normalized % (Argonian = 100% reference, raw max 30).
- `target` — `YES` if `pct < 70` (a parity build target); blank = at parity.
- the 6 dim columns (0-3 each) = the breakdown of what each race has / is missing.
- `richness` — RICH / MODERATE / THIN.

## Visual spec
- **Header:** `Ancestral-Spine Parity — N / 7 at parity` (count races that were targets and now aren't; the 3 RICH races were never targets).
- **Horizontal bars, worst-first** (sort by `pct` asc), one per race:
  - bar length = `pct`; a **vertical line at 70%** (the parity threshold).
  - color: **at parity** (`target` blank, pct >= 70) = green; **target** (`target=YES`) = amber.
  - label: `race  pct%  (done / target)`.
  - Argonian 100% anchors the top.
- **Optional dim mini-breakdown** per race (small segmented bar of the 6 weighted dims:
  boon x3 / sink x2 / minus x2 / renew x1 / dieg x1 / text x1) so a viewer sees WHAT a target is
  missing (e.g. an amber race with renew=0 visibly lacks a renewable channel — ties to 6e).
- Keep it CSS-variable themed + transparent background per the show_widget guidance.

## Update protocol (event-driven, LIVING — not scheduled)
Refresh when a spine build LANDS (a race's registry row changes + an accept commit):
1. `node tools/pdv_spine_stack_score.mjs` (regenerates the ledger from the registry).
2. Re-read `PDV_SpineStackScoreLedger.csv` → re-render the widget.
That's the same event-driven model as the other living charts.
